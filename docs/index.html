Run AI coding agents in parallel — and stack them AI 코딩 에이전트를 병렬로 — 이어지는 작업은 스택으로

Independent work runs in parallel on macOS — each agent in its own isolated git worktree, on its own branch, shipping its own PR. When work builds on work, stack the agents instead and let Wooi keep the stack straight. 독립적인 작업은 macOS 에서 병렬로 — 에이전트마다 격리된 git worktree 위에서, 각자 자기 브랜치로, 각자 자기 PR 로. 이어지는 작업은 앞선 작업 위에 쌓아 두면, 스택 정리는 Wooi 가 맡습니다.

Why Wooi왜 Wooi 인가

One agent at a time is a bottleneck 에이전트를 하나씩 돌리는 건 병목입니다

Wooi removes the wait. Every task gets its own sandbox, so agents never step on each other — and you never lose track of what needs you. Wooi 는 그 기다림을 없앱니다. 작업마다 전용 샌드박스가 주어지므로 에이전트끼리 충돌하지 않고, 사용자 확인이 필요한 세션을 놓칠 일도 없습니다.

🧵

True parallelism진짜 병렬

Kick off a refactor, a feature, and a bugfix at the same time and watch all three from one sidebar. 리팩터링·기능 추가·버그 수정을 한꺼번에 시작하고 사이드바 하나에서 셋 다 지켜봅니다.

🔒

Isolated by default기본이 격리

A separate worktree + branch per task means agents never collide in a shared working tree. 작업마다 별도 worktree + 브랜치라, 공유 작업 트리에서 에이전트끼리 충돌하지 않습니다.

🚢

PR-nativePR 친화적

Jump straight from an agent's diff to a GitHub PR in one click. 에이전트의 diff 에서 GitHub PR 까지 클릭 한 번으로 넘어갑니다.

🧱

Stacked PRs, nativelystacked PR 기본 지원

Stack a workspace on another's branch. When a parent merges, Wooi rebases the children and retargets their PR bases. 워크스페이스를 다른 브랜치 위에 쌓으면, 부모가 병합될 때 자식들을 rebase 하고 PR base 를 옮겨 줍니다.

🕵️

No telemetry텔레메트리 없음

No servers of its own and no analytics. Settings and transcripts stay on your machine, in local storage only. 자체 서버도, 분석 수집도 없습니다. 설정과 대화 기록은 내 컴퓨터 로컬에만 저장됩니다.

How it works동작 방식

Repository → Workspace → PR리포 → 워크스페이스 → PR

One task = one dedicated git worktree + branch + agent session. Nothing runs until you send your first message. 작업 1개 = 전용 git worktree + 브랜치 + 에이전트 세션 1개. 첫 메시지를 보내기 전까지 아무것도 실행되지 않습니다.

01

Connect a repo리포 연결

Point Wooi at a git repository (its main checkout). Configure per-repo Setup / Dev / Archive scripts like npm install. git 리포(메인 체크아웃)를 연결합니다. 리포 단위로 Setup / Dev / Archive 스크립트(npm install 등)를 지정합니다.

02

Spin up a workspace워크스페이스 생성

Each task gets its own worktree + branch + agent session under ~/wooi/workspaces/<repo>/<branch>, running independently and in parallel. 작업마다 전용 worktree + 브랜치 + 세션이 ~/wooi/workspaces/<repo>/<branch> 에 생성되어 독립적·병렬로 실행됩니다.

03

Ship a PRPR 발행

Review the diff against the base branch and open a GitHub PR in one click — while other agents keep working. 다른 에이전트들이 계속 작업하는 동안, base 브랜치 대비 diff 를 검토하고 클릭 한 번으로 GitHub PR 을 엽니다.

Agent support: Wooi currently drives Claude Code via the Claude Agent SDK, reusing your installed Claude Code and gh credentials — no separate API key. Support for more agents such as Codex is planned. 에이전트 지원: Wooi 는 현재 Claude Agent SDK 를 통해 Claude Code 를 구동하며, 설치된 Claude Code 와 gh 의 로그인 정보를 그대로 사용합니다 — 별도 API 키가 필요 없습니다. 앞으로 Codex 등 더 다양한 에이전트를 지원할 예정입니다.
Features기능

Everything you need to run agents in parallel에이전트를 병렬로 돌리는 데 필요한 모든 것

🗂️

Workspaces워크스페이스

  • No default prompt기본 프롬프트 없음 — the input box starts empty; the session begins only when you send your first message. 입력창은 빈 상태로 시작하고, 첫 메시지를 보낼 때 비로소 세션이 시작됩니다.
  • Automatic creation자동 생성 — workspaces get an auto-generated name (like witty-otter) and branch off the default branch. Turn on manual setup to choose the name and base branch yourself. 자동 생성된 이름(witty-otter 등)을 받고 기본 브랜치에서 분기됩니다. 직접 입력을 켜면 이름·베이스 브랜치를 직접 고를 수 있습니다.
  • Per-workspace model & effort워크스페이스별 모델·effort — set from the status line or by typing /model and /effort. Effort ranges through to ultracode. 상태줄에서 고르거나 /model·/effort 로 바꿉니다. effort 는 ultracode 까지 단계가 있습니다.
  • Sessions resume across restarts재시작 간 세션 resume — your conversation context is restored, so the next message continues where you left off. 대화 맥락이 복원되어, 재시작 후 첫 메시지에서 하던 작업을 이어갑니다.
🧱

Stacked PRsStacked PR

  • No extra tooling추가 도구 없음 — not every task is independent — sometimes step 2 builds on step 1. Wooi manages those chains itself with plain git and gh; no Graphite or other stacking CLI needed. 모든 작업이 독립적이지는 않습니다 — 2번 작업이 1번 위에서 이어져야 할 때가 있죠. Wooi 는 그 체인을 git 과 gh 만으로 직접 관리합니다. Graphite 같은 별도 스택 도구가 필요 없습니다.
  • Stack a workspace워크스페이스 쌓기 — pick Stack a new workspace from a workspace's menu; the new one branches off that workspace's branch and its PR targets that branch instead of the default branch. 워크스페이스 메뉴에서 Stack a new workspace 를 고르면 그 브랜치에서 분기한 워크스페이스가 생기고, PR 도 기본 브랜치가 아닌 그 부모 브랜치를 대상으로 열립니다.
  • Stack overview스택 한눈에 — a Stack button in the header lists every branch in the chain with its PR state, PR number, and ahead/behind counts. Click to jump, or open a PR for a branch that doesn't have one. 헤더의 Stack 버튼이 체인의 모든 브랜치를 PR 상태·PR 번호·ahead/behind 와 함께 보여 줍니다. 클릭해 이동하거나, PR 이 없는 브랜치는 그 자리에서 PR 을 엽니다.
  • RestackRestack — rebase a workspace onto the latest parent branch and push with --force-with-lease. Conflicts stop in the worktree so you can resolve them there. 최신 부모 브랜치 위로 rebase 하고 --force-with-lease 로 push 합니다. 충돌이 나면 worktree 에 멈춰 있어 거기서 해결하면 됩니다.
  • Merge cascade병합 캐스케이드 — when a parent PR merges, Wooi retargets each child PR's base to the grandparent branch and rebases the children onto it, so the rest of the stack stays valid. 부모 PR 이 병합되면 각 자식 PR 의 base 를 조부모 브랜치로 옮기고 자식 브랜치를 그 위로 rebase 해, 스택 나머지가 그대로 유효하게 남습니다.
  • Detected, not just declared선언이 아니라 감지 — if an agent builds a chain itself with git checkout -b and gh pr create, Wooi reconstructs the stack from the PRs' base links and shows it the same way. 에이전트가 git checkout -b 와 gh pr create 로 직접 체인을 만들어도, PR 의 base 링크에서 스택을 복원해 똑같이 보여 줍니다.
🛡️

Permissions권한

  • Cycle modes with Shift+TabShift+Tab 으로 모드 순환 — same as Claude Code: default → accept edits → plan → auto. The current mode is shown below the input box. Claude Code 와 동일: default → accept edits → plan → auto. 현재 모드는 입력창 아래에 표시됩니다.
  • "Always allow""Always allow" — permission prompts offer auto-approve for the rest of the session alongside Allow/Deny — Enter = Allow, Esc = Deny. 권한 프롬프트는 Allow/Deny 외에 세션 동안 자동 허용을 제공합니다 — Enter=Allow / Esc=Deny.
👁️

Parallel-session visibility병렬 세션 가시화

  • Status at a glance한눈에 보는 상태 — the sidebar distinguishes running (spinner), awaiting permission (yellow shield), and unread responses (blue dot). 사이드바에서 실행 중(spinner)·권한 대기(노란 방패)·미확인 응답(파란 점)을 구분해 보여줍니다.
  • OS notifications & Dock badgeOS 알림 · Dock 배지 — when the window is inactive, completions / errors / permission requests appear as notifications and a Dock badge count. 창이 비활성이면 완료·에러·권한 요청을 OS 알림으로 띄우고 Dock 배지에 집계합니다.
  • Jump to what needs you확인 필요한 곳으로 이동 — "Needs input" / "Next unread" buttons jump straight to the session that needs you. "Needs input / Next unread" 버튼으로 사용자 확인이 필요한 세션으로 바로 이동합니다.
  • Overview boardOverview 보드 — lists every active session with status filters (All / Running / Needs input / Unread / Idle) and a Stop all action. 모든 활성 세션을 상태별 필터(All / Running / Needs input / Unread / Idle)로 훑고 Stop all 로 일괄 중단합니다.
🧰

Work area작업 영역

  • All filesAll files — a file tree of the worktree with a read-only, syntax-highlighted viewer. worktree 파일 트리와 읽기 전용·구문 강조 뷰어.
  • ChangesChanges — a per-file diff against the base branch (same as a PR diff), covering commits + staged + unstaged + untracked. A Create PR button opens GitHub's PR page. base 브랜치 대비 파일별 diff(PR diff 와 동일). 커밋 + staged + unstaged + untracked 를 모두 포함하고, Create PR 버튼이 PR 작성 화면을 엽니다.
  • CheckCheck — CI check results for the PR on the current branch. 현재 브랜치 PR 의 CI 체크 결과.
  • TerminalTerminal — a per-workspace login-shell terminal that survives workspace switches, preserving running commands and shell state. workspace 별 로그인 셸 터미널. 전환했다 돌아와도 실행 중이던 명령과 셸 상태가 유지됩니다.
✍️

Composing messages메시지 작성

  • Slash-command autocomplete슬래시 명령 자동완성 — type / to see the Claude Code commands/skills available in that worktree. / 를 치면 해당 worktree 에서 쓸 수 있는 명령/스킬 목록이 뜹니다.
  • Inline shell commands인라인 셸 명령 — start a message with ! to run it as a shell command, with output shown right in the chat. 메시지를 ! 로 시작하면 셸 명령으로 실행되고 결과가 채팅에 바로 표시됩니다.
  • Image attachments이미지 첨부 — paste or drop images into the input box to send them along. 입력창에 이미지를 붙여넣거나 끌어다 놓으면 함께 전송됩니다.
  • Status line & auto-compact상태줄 · 자동 압축 — branch · directory · model · effort · context usage always shown; long conversations auto-compact, or run /compact manually. 브랜치 · 디렉토리 · 모델 · effort · 컨텍스트 사용량이 항상 표시되고, 길어지면 자동 압축되거나 /compact 로 수동 압축합니다.
  • Drafts, queueing & shortcuts초안·큐잉·단축키 — in-progress messages survive workspace switches; queue follow-ups while a turn runs; ↑/↓ recall messages, ⌘1–9 and ⌘[ ⌘] switch workspaces. 작성 중 메시지는 전환에도 유지되고, 실행 중 후속 메시지를 큐에 넣습니다. ↑/↓ 로 이전 메시지, ⌘1–9 / ⌘[ ⌘] 로 전환합니다.
Get started시작하기

Install in a couple of minutes몇 분이면 설치 완료

Download the latest build, drag it in, and finish a quick onboarding. 최신 빌드를 받아 드래그하고, 간단한 온보딩만 마치면 됩니다.

1

Download & drag to Applications다운로드 후 Applications 로 드래그

Download the latest .dmg and drag Wooi into Applications. Older builds live on the Releases page. 최신 .dmg 를 받아 Wooi 를 Applications 로 드래그합니다. 이전 빌드는 Releases 페이지에 있습니다.

2

Onboarding: consent & sign in온보딩: 동의 & 로그인

Consent to the Terms/Privacy, then sign in to Claude (finishes in-app via your browser) and GitHub (opens your Terminal). The gh CLI is required — a hard gate blocks the app until it's installed and signed in. 약관·개인정보처리방침에 동의한 뒤 Claude(앱 안에서 브라우저로 마무리)와 GitHub(Terminal 에서 진행)에 로그인합니다. gh CLI 는 필수라, 설치·로그인 전에는 하드 게이트가 앱 진입을 막습니다.

🚫

No analytics분석 없음

Wooi has no servers of its own and collects no analytics or telemetry. Wooi 는 자체 서버가 없고 분석·텔레메트리를 수집하지 않습니다.

🔗

Direct to providers공급자로 직접 전송

Prompts & code go to Anthropic via the Claude Agent SDK; PR metadata goes to GitHub via the gh CLI. 프롬프트·코드는 Claude Agent SDK 로 Anthropic 에, PR 메타데이터는 gh CLI 로 GitHub 에 전송됩니다.

💾

Local only로컬에만 저장

Settings & transcripts are stored locally in ~/Library/Application Support/Wooi/. 설정·대화 기록은 ~/Library/Application Support/Wooi/ 에만 저장됩니다.
